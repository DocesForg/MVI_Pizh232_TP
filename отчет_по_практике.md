## Тема: Разработка виджета быстрого доступа к платежам для Android-приложения

---

## Введение

В современном мире мобильные приложения становятся основным инструментом для взаимодействия пользователей с финансовыми сервисами. Одним из ключевых требований к современным приложениям является обеспечение быстрого доступа к часто используемым функциям без необходимости полного запуска приложения.

**Целью данной практики** являлась разработка и интеграция виджета для домашнего экрана Android-устройства, предоставляющего пользователю быстрый доступ к информации о предстоящих платежах и возможность перехода к форме оплаты в одно касание.

**Задачи практики:**
1. Провести анализ предметной области мобильных виджетов в экосистеме Android
2. Спроектировать архитектуру взаимодействия виджета с основным приложением
3. Реализовать функционал виджета с использованием RemoteViews и PendingIntent
4. Обеспечить двустороннее взаимодействие между виджетом и основным приложением
5. Провести тестирование и отладку разработанного решения

**Объект исследования:** процесс разработки виджетов для операционной системы Android.

**Предмет исследования:** программная реализация виджета быстрого доступа к платежам с использованием Android AppWidget API.

## Анализ предметной области и проектирование решения

### 2.1 Обзор технологии Android AppWidget

Android AppWidget — это механизм, позволяющий размещать интерактивные элементы управления приложениями непосредственно на домашнем экране устройства. Виджеты представляют собой уменьшенные представления приложений, которые обновляются периодически или по событию.

**Ключевые компоненты системы виджетов:**
- **AppWidgetProvider** — BroadcastReceiver, обрабатывающий события жизненного цикла виджета
- **RemoteViews** — структура данных для описания пользовательского интерфейса виджета
- **PendingIntent** — механизм отложенного выполнения действий от имени другого приложения
- **AppWidgetManager** — системный сервис для управления установленными виджетами

### 2.2 Требования к разрабатываемому виджету

На основе анализа предметной области были сформулированы следующие требования:

**Функциональные требования:**
1. Отображение списка предстоящих платежей (до 3 элементов)
2. Возможность перехода к форме оплаты по клику на платеж
3. Возможность скрытия платежа из виджета без удаления
4. Автоматическое обновление данных при изменении состояния приложения
5. Отображение сообщения при отсутствии данных

**Нефункциональные требования:**
1. Минимальное потребление ресурсов в фоновом режиме
2. Поддержка изменения размеров виджета
3. Совместимость с различными версиями Android
4. Период обновления не чаще 30 минут для экономии батареи

### 3.4 Логика работы виджета

Основной класс `QuickPaymentWidgetProvider` наследуется от `AppWidgetProvider`:

#### 3.4.1 Метод onUpdate()

Отвечает за отрисовку содержимого виджета:

```kotlin
override fun onUpdate(
    context: Context,
    appWidgetManager: AppWidgetManager,
    appWidgetIds: IntArray
) {
    appWidgetIds.forEach { appWidgetId ->
        appWidgetManager.updateAppWidget(appWidgetId, buildViews(context))
    }
}
```

Для каждого экземпляра виджета вызывается метод `buildViews()`, который формирует RemoteViews.

#### 3.4.2 Метод buildViews()

Формирует представление виджета на основе актуальных данных:

```kotlin
private fun buildViews(context: Context): RemoteViews {
    val payments = PaymentsRepository(context).loadWidgetPayments(3)
    val views = RemoteViews(context.packageName, R.layout.widget_quick_payment)
    
    val rows = listOf(
        Triple(R.id.row1, R.id.widgetPayment1, R.id.widgetDelete1),
        Triple(R.id.row2, R.id.widgetPayment2, R.id.widgetDelete2),
        Triple(R.id.row3, R.id.widgetPayment3, R.id.widgetDelete3)
    )
    
    if (payments.isEmpty()) {
        // Показать сообщение о пустом состоянии
        rows.forEach { (rowId, _, _) -> views.setViewVisibility(rowId, View.GONE) }
        views.setViewVisibility(R.id.widgetEmpty, View.VISIBLE)
    } else {
        // Заполнить строки данными о платежах
        views.setViewVisibility(R.id.widgetEmpty, View.GONE)
        rows.forEachIndexed { index, (rowId, textId, deleteId) ->
            if (index < payments.size) {
                val payment = payments[index]
                views.setViewVisibility(rowId, View.VISIBLE)
                views.setTextViewText(textId, "${payment.title} • ${payment.amount} ₽ (${payment.dueDate})")
                views.setOnClickPendingIntent(textId, openPaymentIntent(context, payment, index))
                views.setOnClickPendingIntent(deleteId, hideFromWidgetIntent(context, payment.id, index))
            } else {
                views.setViewVisibility(rowId, View.GONE)
            }
        }
    }
    
    return views
}
```

**Ключевые операции:**
1. Загрузка данных через `PaymentsRepository.loadWidgetPayments(3)`
2. Динамическое управление видимостью элементов
3. Назначение PendingIntent для интерактивных элементов

#### 3.4.3 Метод onReceive()

Обрабатывает кастомные действия виджета:

```kotlin
override fun onReceive(context: Context, intent: Intent) {
    super.onReceive(context, intent)
    if (intent.action == ACTION_HIDE_FROM_WIDGET) {
        val paymentId = intent.getStringExtra(EXTRA_PAYMENT_ID).orEmpty()
        if (paymentId.isNotBlank()) {
            PaymentsRepository(context).hideFromWidget(paymentId)
            forceUpdate(context)
        }
    }
}
```

**Обработка действия скрытия:**
1. Извлечение идентификатора платежа из Intent
2. Вызов метода репозитория для добавления в список скрытых
3. Принудительное обновление всех экземпляров виджета

#### 3.4.4 Создание PendingIntent

Для обработки кликов создаются два типа PendingIntent:

**Открытие формы оплаты:**
```kotlin
private fun openPaymentIntent(context: Context, payment: UpcomingPayment, requestCode: Int): PendingIntent {
    val intent = Intent(context, MainActivity::class.java).apply {
        putExtra("open_screen", "payment")
        putExtra("title", payment.title)
        putExtra("account", payment.account)
        putExtra("amount", payment.amount.toString())
    }
    return PendingIntent.getActivity(
        context,
        2000 + requestCode,
        intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )
}
```

**Скрытие платежа из виджета:**
```kotlin
private fun hideFromWidgetIntent(context: Context, paymentId: String, requestCode: Int): PendingIntent {
    val intent = Intent(context, QuickPaymentWidgetProvider::class.java).apply {
        action = ACTION_HIDE_FROM_WIDGET
        putExtra(EXTRA_PAYMENT_ID, paymentId)
    }
    return PendingIntent.getBroadcast(
        context,
        3000 + requestCode,
        intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )
}
```

**Использование флагов:**
- `FLAG_UPDATE_CURRENT` — обновление существующего PendingIntent с новыми данными
- `FLAG_IMMUTABLE` — требование безопасности Android 12+ для неизменяемых PendingIntent

#### 3.4.5 Метод forceUpdate()

Статический метод для принудительного обновления виджета из любого компонента приложения:

```kotlin
companion object {
    fun forceUpdate(context: Context) {
        val manager = AppWidgetManager.getInstance(context)
        val component = ComponentName(context, QuickPaymentWidgetProvider::class.java)
        manager.getAppWidgetIds(component).forEach { id ->
            manager.updateAppWidget(id, buildViews(context))
        }
    }
}
```

## Взаимодействие виджета с основным приложением

### 4.1 Регистрация виджета в Manifest

Для корректной работы виджет должен быть зарегистрирован в AndroidManifest.xml:

```xml
<receiver
    android:name=".widget.QuickPaymentWidgetProvider"
    android:exported="false">
    <intent-filter>
        <action android:name="android.appwidget.action.APPWIDGET_UPDATE" />
    </intent-filter>
    <meta-data
        android:name="android.appwidget.provider"
        android:resource="@xml/quick_payment_widget_info" />
</receiver>
```

**Важные аспекты:**
- `android:exported="false"` — виджет доступен только внутри приложения
- Intent-фильтр слушает системное событие APPWIDGET_UPDATE
- Meta-data связывает receiver с конфигурационным XML

### 4.2 Передача данных от виджета к приложению

При клике на платеж в виджете происходит переход в MainActivity с передачей данных:

```kotlin
// В виджете
val intent = Intent(context, MainActivity::class.java).apply {
    putExtra("open_screen", "payment")
    putExtra("title", payment.title)
    putExtra("account", payment.account)
    putExtra("amount", payment.amount.toString())
}

// В MainActivity
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContent {
        AppNav(
            viewModel = viewModel,
            openPaymentDirectly = intent?.getStringExtra("open_screen") == "payment",
            intentTitle = intent?.getStringExtra("title").orEmpty(),
            intentAccount = intent?.getStringExtra("account").orEmpty(),
            intentAmount = intent?.getStringExtra("amount").orEmpty()
        )
    }
}
```

**Навигационная логика:**
1. Проверка параметра `open_screen` определяет начальный экран
2. При значении "payment" навигация начинается сразу с формы оплаты
3. Данные платежа подставляются в поля формы автоматически

### 4.3 Синхронизация данных через Repository

Единый источник данных — `PaymentsRepository` — обеспечивает консистентность:

```kotlin
class PaymentsRepository(context: Context) {
    private val prefs = context.getSharedPreferences(PREFS_NAME, Context.MODE_PRIVATE)
    
    // Хранение скрытых платежей
    fun hideFromWidget(paymentId: String) {
        val hidden = loadHiddenInWidgetIds().toMutableSet().apply { add(paymentId) }
        saveHiddenInWidgetIds(hidden)
    }
    
    // Загрузка с учетом скрытых
    fun loadWidgetPayments(limit: Int = 3): List<UpcomingPayment> {
        val hidden = loadHiddenInWidgetIds()
        return loadCache().filterNot { it.id in hidden }.take(limit)
    }
}
```

**Механизм хранения:**
- Данные сохраняются в SharedPreferences
- Отдельный ключ `WIDGET_HIDDEN_IDS_KEY` для скрытых платежей
- Фильтрация происходит при каждой загрузке данных

### 4.4 Интеграция с ViewModel

MainViewModel координирует взаимодействие между UI и виджетом:

```kotlin
class MainViewModel(application: Application) : AndroidViewModel(application) {
    private val repository = PaymentsRepository(application)
    
    fun refresh() {
        viewModelScope.launch {
            _uiState.value = UiState(loading = true)
            val payments = repository.getUpcomingPayments()
            _uiState.value = UiState(loading = false, payments = payments)
            QuickPaymentWidgetProvider.forceUpdate(getApplication())
        }
    }
    
    fun deletePayment(paymentId: String) {
        repository.deletePayment(paymentId)
        _uiState.value = _uiState.value.copy(payments = ...)
        QuickPaymentWidgetProvider.forceUpdate(getApplication())
    }
    
    fun restoreToWidget(paymentId: String) {
        repository.unhideFromWidget(paymentId)
        QuickPaymentWidgetProvider.forceUpdate(getApplication())
    }
}
```

**Сценарии синхронизации:**
1. **Обновление списка** — после загрузки данных из сети
2. **Удаление платежа** — виджет обновляется автоматически
3. **Восстановление в виджет** — при нажатии "Оплатить" в основном приложении

### 5.3 Проблемы и решения

**Проблема 1: PendingIntent не обновляется**

*Симптом:* При клике открываются данные первого платежа

*Решение:* Использование уникальных requestCode для каждого PendingIntent:
```kotlin
PendingIntent.getActivity(context, 2000 + requestCode, ...)
PendingIntent.getBroadcast(context, 3000 + requestCode, ...)
```

**Проблема 2: Виджет не обновляется после изменения данных**

*Симптом:* Данные в виджете устарели после операции в приложении

*Решение:* Явный вызов `forceUpdate()` после каждой модификации данных:
```kotlin
fun deletePayment(paymentId: String) {
    repository.deletePayment(paymentId)
    QuickPaymentWidgetProvider.forceUpdate(getApplication())
}
```

**Проблема 3: Crash на Android 12+**

*Симптом:* Приложение аварийно завершается при создании PendingIntent

*Решение:* Добавление флага `FLAG_IMMUTABLE`:
```kotlin
PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
```
